# ADR-0003: Tiered identity matching with explicit confidence

- **Status:** Accepted
- **Date:** 2026-08-16

## Context

Every statement mepdiff makes rests on a claim that some element in snapshot A
is the same element in snapshot B. Get identity wrong and the entire report is
wrong in a way that looks plausible: a mismatched pair reads as a large property
change, and an unmatched pair reads as a deletion plus an addition.

Stable identifiers do not solve this on their own. IFC `GlobalId` is usually
stable for elements exported repeatedly from the same authoring model, because
Revit derives it from the element's `UniqueId` — but it is not guaranteed.
Elements regenerated by editing operations get new identifiers, ports are
frequently reissued, and identifiers do not survive a move between authoring
tools or a model rebuild at all. Meanwhile the elements engineers care about
carry something better: a human-assigned mark, `VAV-12`, which is stable
precisely because a person is maintaining it.

There is a second requirement beyond accuracy. This tool is meant for handover
and audit. A diff that cannot be checked is not evidence.

## Decision

Resolve identity in tiers, most reliable first, over the skeleton nodes from
ADR-0002:

- **Tier 0 — stable identifier.** `GlobalId` (IFC) or `UniqueId` (Revit), accepted
  only when the element class also agrees, so that a recycled identifier cannot
  match a diffuser to a damper.
- **Tier 1 — semantic key.** Class plus human mark or name, scoped within a
  system. This is what rescues rebuilt and re-exported models.
- **Tier 2 — structural score.** For whatever remains, score candidates on class
  agreement, attribute similarity, proximity of placement, and how many of their
  neighbours are already matched. Anchoring on tiers 0 and 1 makes this
  tractable: it is a local assignment problem, not graph isomorphism.
- **Tier 3 — unmatched.** Reported as added or removed.

**Every match carries a confidence and a human-readable reason**, and the reason
is surfaced in the report, not buried in a debug log:

```
VAV-12    matched by GlobalId + Mark, 4/5 neighbours agree    confidence 0.98
```

Ambiguous matches are reported as ambiguous rather than silently resolved.

**Tier 2 is built last** — after the golden-file harness exists (M9, not M5).

## Consequences

- The report is auditable. A reviewer who distrusts a finding can see what the
  match was based on and overrule it. For a handover artefact this is the
  difference between a claim and evidence.
- Confidence must propagate. A downstream airflow delta computed across a
  low-confidence match is itself low-confidence, and reporting it at full
  confidence would be a lie of omission.
- Deferring tier 2 means early versions over-report added/removed pairs on
  rebuilt models. This is the correct failure direction: a visible false
  deletion invites scrutiny, while a wrong fuzzy match silently corrupts
  everything computed from it.
- Building tier 2 last is deliberate discipline. It is the most interesting part
  and therefore the most tempting to build first, but it is untunable without
  real messy files and unsafe to change without regression tests. Both arrive
  before it does.
- Tier 1 inherits whatever discipline the model has. Duplicate marks and blank
  marks are common in practice, so tier 1 must detect non-unique keys and
  decline rather than guess.

## Alternatives considered

**Trust `GlobalId` alone.** Simple, and correct often enough to be dangerous. It
fails exactly where the tool is most needed — across rebuilds, across tools, and
after the kind of large edit that makes people want a diff in the first place.

**Pure geometric matching.** Rejected: it makes an element that moved
unrecognisable, and movement is normal between revisions.

**Full graph-isomorphism matching.** Rejected as a primary mechanism —
expensive, and it produces mathematically valid matches that are engineering
nonsense, with no reason a reviewer could evaluate.

**A single blended similarity score instead of tiers.** Rejected because it
destroys explainability. "Score 0.83" tells a reviewer nothing; "GlobalId
matched" tells them everything.
